## 2. Data Flow Diagram

### Add Product Flow
```
User → FAB Click → _showProductDialog() 
  → Form Submission 
  → ProductsProvider.addProduct(data) 
  → Firestore: products.add(data) 
  → fetchProducts() [refresh] 
  → fetchCategories() [extract new category]
  → notifyListeners() [UI rebuild]
  → SnackBar: "Product added"
```

### Edit Product Flow
```
User → Edit Icon → _showEditProductDialog(product)
  → Form Pre-populated with Product data
  → Category Dropdown shows current + other options
  → Form Submission
  → ProductsProvider.updateProduct(id, data)
  → Firestore: products.doc(id).update(data)
  → fetchProducts() [refresh]
  → fetchCategories() [sync categories]
  → notifyListeners() [UI rebuild]
  → SnackBar: "Product updated"
```

### Category Management Flow
```
[Scenario 1: Existing Category]
Dropdown Selection → Category from productsProvider.categories
  → Form Submitted → Saved to product.category field

[Scenario 2: Custom Category]
Select "Other" → Conditional TextField appears
  → User types new category (e.g., "Sports")
  → Form submitted → Saved as product.category = "Sports"
  → Next time fetchCategories() runs → "Sports" extracted and added to dropdown
```

## 3. Technical Decisions & Patterns

### 3.1 Why StatefulBuilder in Dialogs?
```dart
showDialog(
  context: context,
  builder: (ctx) => StatefulBuilder(
    builder: (ctx, setState) => AlertDialog(...)
```

**Reason:** StatefulBuilder allows form state (like `showCustomCategory` boolean) to update locally within the dialog without rebuilding the entire page. This is more performant than having the whole AdminPage rebuild.

### 3.2 Why Consumer<ProductsProvider> in Dialog?
```dart
Consumer<ProductsProvider>(
  builder: (context, productsProvider, child) {
    var categories = productsProvider.categories.toList();
```

**Reason:** Consumer provides reactive updates. When categories change in the provider, the dropdown rebuilds automatically. This ensures categories are always current.

### 3.3 Why Call fetchCategories() After fetchProducts()?
```dart
Future<void> fetchProducts() async {
  // ... fetch products ...
  await fetchCategories();  // Always called after
  _isLoading = false;
  notifyListeners();
}
```

**Reason:** This ensures categories are extracted from the latest product data. If a new product is added with a new category, `fetchCategories()` will capture it. This guarantees the dropdown is always up-to-date.

### 3.4 Why Ensure "General" is in Dropdown?
```dart
if (!categories.contains("General")) {
  categories.insert(0, "General");
}
```

**Reason:** DropdownButton requires the `value` to exist in `items` list. If selectedCategory is "General" but the list doesn't contain it, the widget crashes. Defensive programming ensures robustness.

## 4. Error Handling Strategy

### 4.1 Firestore Errors (ProductsProvider)
```dart
try {
  await FirebaseFirestore.instance.collection('products').add(productData);
} on FirebaseException catch (e) {
  debugPrint("❌ Firebase error: ${e.code} - ${e.message}");
  rethrow;  // Let caller handle
} catch (e) {
  debugPrint("❌ Unexpected error: $e");
  rethrow;
}
```

**Strategy:**
1. Catch FirebaseException separately for Firestore-specific errors
2. Log with emoji prefixes for easy debugging (❌ error, ✅ success)
3. Rethrow to allow caller to show UI feedback

### 4.2 UI Feedback (AdminPage)
```dart
try {
  await Provider.of<ProductsProvider>(context, listen: false)
      .addProduct(data);
  if (mounted) CustomSnackBar.show(context, "Product added");
} catch (e) {
  if (mounted) CustomSnackBar.show(context, "Error: $e", isError: true);
}
```

**Strategy:**
1. Wrap provider calls in try-catch
2. Check `mounted` before showing UI (prevents crashes if dialog closes)
3. Use CustomSnackBar for consistent error feedback

## 5. State Management Best Practices

### 5.1 When to Use notifyListeners()
```dart
// ✅ Good: Notify after state change
_products = newList;
notifyListeners();  // UI rebuilds with new data

// ❌ Bad: Notify without state change
notifyListeners();  // Unnecessary rebuild

// ✅ Good: Notify at end of async operation
async void fetchProducts() async {
  _isLoading = true;
  notifyListeners();
  try {
    // ... fetch data ...
    _isLoading = false;
    notifyListeners();  // Final state update
  }
}
```

### 5.2 Immutable Getters
```dart
List<String> get categories => [..._categories];  // Copy, not reference
List<Product> get products => [..._products];     // Copy, not reference
```

**Reason:** Prevents external code from modifying internal state directly. Changes must go through provider methods.

## 6. UI Components & Widgets

### 6.1 DropdownButton<String>
```dart
DropdownButton<String>(
  value: selectedCategory,              // Current selection
  isExpanded: true,                     // Take full width
  onChanged: (value) {                  // Callback on selection
    setState(() {
      selectedCategory = value ?? "General";
      showCustomCategory = (value == "Other");
    });
  },
  items: [                              // List of options
    ...categories.map((cat) => DropdownMenuItem(
      value: cat,
      child: Text(cat),
    )),
    const DropdownMenuItem(              // Custom option
      value: "Other",
      child: Text("Other"),
    ),
  ],
)
```

## 7. Database Schema (Firestore)

### 7.1 Products Collection
```
/products/{documentId}
{
  "name": "Wireless Headphones",
  "price": 1200.0,
  "description": "High-quality Bluetooth headphones",
  "category": "Electronics",          // This field is extracted by fetchCategories()
  "imageUrl": "https://images.unsplash.com/...",
  "createdAt": Timestamp(...)
}
```

### 7.2 Category Extraction Algorithm
```dart
Future<void> fetchCategories() async {
  final categoriesSet = <String>{'General'};  // Always include default
  
  for (final doc in snapshot.docs) {
    final category = doc.data()['category'] as String?;
    if (category != null && category.isNotEmpty) {
      categoriesSet.add(category);  // Add to set (duplicates ignored)
    }
  }
  
  _categories = categoriesSet.toList()..sort();  // Convert to list, sort
}
```

## 10. Debugging Tips

### 10.1 Enable Debug Logging
```dart
debugPrint("[AdminPage] Product dialog opened");
debugPrint("🔍 Fetching products from Firestore...");
debugPrint("✅ Successfully loaded ${_products.length} products");
debugPrint("❌ Error updating product: $e");
```

**Tip:** Search for emoji in Xcode/Android Studio console to filter logs

### 10.2 Common Errors & Solutions

| Error | Cause | Solution |
|-------|-------|----------|
| "DropdownButton's value: 'Home' is not in items list" | Selected value not in dropdown items | Ensure value exists in items list before building |
| "Failed to update product" | Firestore permission denied | Check Firestore security rules |
| "Null check operator used on null value" | Product is null after fetch | Add null safety checks |
| "RenderFlex overflowed" | Dialog too large for screen | Add `SingleChildScrollView` |
